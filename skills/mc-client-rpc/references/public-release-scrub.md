# 公开发布前脱敏验收（转公开仓库的门禁）

触发点：要把本工具仓 push 到公开 GitHub 之前。工作区扫描干净 ≠ 可以公开，按本清单走完再发。

## 门禁顺序

1. **私有内容分类**：部署/业务脚本 vs 通用工具脚本，判据见 `deploy-and-verify.md` 的
   「迁出还是留、按证据分」。业务脚本整只迁到私有被测项目仓（私网配置留在私有侧），
   不脱敏保留在工具仓。
2. **参数化泛化**：主机/端口/密码/工程路径全部改环境变量（契约表见仓库 README），
   默认只允许回环，缺失时明确报错而非静默回退。改库默认值时保持函数签名向后兼容
   （位置参数不动，只换默认值来源），既有调用点和已迁出副本才不用跟着改。
3. **文档泛化**：示例地址一律用文档保留段（`203.0.113.0/24`、`2001:db8::/32`、
   `example.com`），不用真实内网地址；定位描述不点名私有被测项目。
4. **全仓复扫（门禁，CLEAN 才算过）**：跑本技能 `scripts/scrub_scan.py`。内置通用模式
   （RFC1918 地址、`C:\Users\<用户>`、盘符绝对路径、`/home/<用户>`、硬编码密钥赋值）；
   项目专属私值（具体 IP/用户名/项目名/专用 env 名）用 `--patterns-file` 从仓库外传入。
   **私值清单绝不能写进待公开仓库的任何文件**——清单本身也是私值。命中是候选不是
   判决，逐条人工核（注释里的示例值 vs 真值）。
5. **git 历史门**：以上只清理工作区，历史提交里的旧私值仍可被 clone 者从历史 diff 翻出。
   转公开前必须交用户拍板：`git filter-repo` 重写历史（改哈希、要强推），或书面接受
   「内网测试机地址非机密」。发布决策权在用户，agent 不自行重写历史、不自行 push。

## 提交纪律

脱敏改动分批小步 commit（库 → 脚本 → 文档 → 配置类各一批），中文 message 写根因/修法/副作用。
