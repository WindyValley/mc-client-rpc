# 交接总览

本文是 mc-client-rpc 工程交接的入口，帮助接手者快速理解「这是什么、当前到哪了、有哪些约束和坑、接下来做什么」。

## 一句话定位

mc-client-rpc 是一个 **Minecraft 客户端内的 JSON-RPC 控制框架**：在客户端进程内监听 TCP（默认 25586），把外部请求转成对客户端真实输入 API 的调用，驱动一个真实连入服务器的玩家，用于真机行为自动化操控与验证。

## 当前能力

- **双加载器**：Fabric + NeoForge（平台入口薄，业务全在 common）。
- **客户端导航**：状态查询、回主菜单、连接 / 断开、退出进程。
- **单机存档**：列举本机存档、按参数创建并进入世界（种子/模式/难度/作弊/类型）、进入已有存档——全部走官方 `WorldOpenFlows` 路径（与真人点按钮 / quickPlay 单机等价）。
- **玩家操控**：视角、真实按键移动、跳跃、停止、走向目标、攻击、自动寻路攻击。
- **命令 / 聊天**：以玩家身份发送斜杠命令或聊天。
- **世界查询**：列出周围生物。

完整方法清单见 [rpc-api.md](rpc-api.md)。

## 关键事实（接手前必须知道）

1. **MC 状态只能在 render thread 访问**。网络线程的请求必须经任务队列切到客户端 tick 执行。详见线程模型。
2. **绝不在 render thread 上阻塞**，否则死锁。
3. **真实输入靠驱动按键映射**（`KeyMapping.setDown`），不能直改输入字段（被 tick 覆盖）、不能直调实体方法（不发包）。详见输入模拟。
4. **按键是持续状态**，用完要 `player.stop` 释放。
5. **判据以服务端权威为准**，客户端返回的血量是即时预测。

## 已知约束 / 风险

| 项 | 说明 | 应对 |
|----|------|------|
| **无鉴权** | 任何能连上端口的本机程序即可操控角色 | 默认只绑 127.0.0.1；切勿暴露公网 |
| **无 CI** | 目前没有自动构建/测试工作流 | 需要时补 GitHub Actions |
| **操控层无单测** | 强依赖真实 MC runtime | 用真机自动化覆盖（见 real_device_test.py）|
| ~~测试服务器耦合~~ | 已解除：host 为必传参数，无默认地址 | — |

## 建议的后续工作

按优先级：

1. 合并文档分支后，按需补一个最小 CI（构建 + `test`）。
2. 把操控层里能脱离 MC 的判定（参数解析、门槛值）抽成可单测的纯逻辑。
3. 若未来需要 OS 物理级键鼠时序，在**外部测试脚本**侧实现，不进 mod。
4. 随使用场景扩展 RPC 方法时，保持协议层与 MC 解耦、在 render thread 执行的约束。

## 快速上手

```bash
# 构建
./gradlew build

# 协议层单测
./gradlew test

# 启动 NeoForge 客户端（runClient 已预置离线连测试服参数）
./gradlew :neoforge:runClient

# 客户端起来后，从外部发一条命令测试
echo '{"jsonrpc":"2.0","method":"client.status","id":1}' | nc 127.0.0.1 25586
```
