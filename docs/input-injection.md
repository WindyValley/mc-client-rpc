# 输入模拟方案

「怎么让客户端发出真实的移动/攻击/跳跃」是本框架最核心的技术决策，经历了三种方案的实测取舍。本文记录每条路径、实测现象与最终选择，避免后来者重走弯路。

## 判定一条输入方案好坏的标准

1. 服务端是否真的看到了动作（位置/攻击包）；
2. 是否走原版输入链路（动画、脚步声、振动、冷却等是否自然）；
3. 是否只影响目标动作、不产生副作用。

## 方案一：直接改输入字段 ❌

做法：设置 `LocalPlayer.input` 上的字段，如 `forwardImpulse`、`leftImpulse`、`jumping`。

实测现象：
- 玩家原地不动，坐标恒定；
- 跳跃不触发。

根因：`KeyboardInput.tick()` 每一帧开头会根据**键盘按键映射的真实状态**重算这些字段，把外部写入立即覆盖。即使在 `CLIENT_POST` 之后重设，下一帧 tick 又被清掉。

结论：设了等于白设。

## 方案二：客户端线程直接调用实体方法 ❌

做法：在客户端直接调实体方法，如 `LocalPlayer.jumpFromGround()`。

实测现象：
- 玩家**本地确实离地**（如 y 从 -57 抬到 -55.8）；
- 但服务端监听器（如尖啸体）毫无反应，`listener tick` 恒为 -1。

根因：这种调用发生在**正常 tick 循环之外**，只触发了客户端的本地预测，**不发位置包**。等下一帧正常 tick 发位置包时，玩家已经落地回原位，服务端从头到尾没看到这次跳跃，于是服务端不产生落地振动等权威事件。

结论：能骗过本地画面，骗不过服务端。

## 方案三：驱动按键映射 ✅（最终采用）

做法：不碰输入字段、不直调实体方法，而是直接设置 **Minecraft 按键映射（`KeyMapping`）的按下状态**，后续完全交给原版链路。

`player.move` / `player.jump` 操作的按键：

| 按键映射 | 对应参数 |
|----------|----------|
| `options.keyUp` | `forward > 0` |
| `options.keyDown` | `forward < 0` |
| `options.keyLeft` | `strafe > 0` |
| `options.keyRight` | `strafe < 0` |
| `options.keyJump` | `jump` |

`KeyMapping.setDown(boolean)` 是 public 方法，可在 render thread 直接调用。

之后走的是真人按键的完整原版链路：

```
KeyMapping.setDown(true)
      ▼
KeyboardInput.tick() 读到「已按下」→ 设置 input.forwardImpulse / jumping
      ▼
LocalPlayer.aiStep() 移动 / 起跳
      ▼
正常网络管线发出 位置包 / 攻击包
      ▼
服务端看到真实动作（位移、落地振动、攻击判定）
```

实测结果：移动约 **4.5 格/秒**（与真人走速一致），服务端可见跳跃与落地。

结论：这是唯一同时满足「服务端可见」「走原版链路」「副作用最小」的方案。

## 使用方案三的注意事项

- 按键是**持续状态**。脚本结束、换动作或测试结束前，必须 `player.stop`（或对应 `down=false`）释放，否则角色会一直走/跳。
- 不同动作的真实性来自具体游戏事件。例如尖啸体只监听 STEP（走动），跳跃/落地事件不在其监听标签里——要触发它得让玩家走动，不是原地跳。
- 攻击走 `mc.gameMode.attack(player, target)` + `swing`，发的是真实攻击包（`ServerboundInteractPacket`）。

## OS 级真实键鼠模拟：不放进 mod

真实度最高的做法是直接给游戏窗口发 OS 键鼠消息（如 Windows 的窗口消息、pywin32）。但本框架**刻意不**把它放进 mod，原因：

- 平台相关代码会污染 JAR；
- 依赖操作系统，跨平台难维护；
- mod 内驱动按键映射已能覆盖绝大多数「服务端可见的真实输入」需求。

因此架构约定：**OS 级模拟放外部测试脚本侧，mod 只负责驱动按键映射**。如果将来某场景按键映射不够（需要真实物理按键级时序），应在测试脚本里加，而不是改本 mod。

## 小结

| 方案 | 客户端表现 | 服务端可见 | 结论 |
|------|-----------|-----------|------|
| 改输入字段 | 不动 | 否 | ❌ 被 tick 覆盖 |
| 直调实体方法 | 本地动 | 否 | ❌ 不发包 |
| 驱动按键映射 | 正常 | 是 | ✅ 采用 |
| OS 级窗口消息 | 正常 | 是 | 放脚本侧，不进 mod |
